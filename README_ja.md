## 概要
Codexion は C 言語で記述された高性能なコンカレンシーおよびリソース同期シミュレーションです。バーンアウト（燃え尽き）を起こさずに量子コードをコンパイルするため、複数のコーダーが限られた共有開発リソース（USB ドングル）を奪い合う複雑なマルチスレッド環境をモデリングしています。
リソース共有を制御し、デッドロックを防止し、公平なアクセスを確保するために、POSIX スレッド、Mutex、条件変数、および高度なスケジューリングアルゴリズム（FIFO / EDF）を実装しています。

## 使用方法
1. プログラムをコンパイルして実行可能ファイルを生成します:

    `make`

2. プログラムを実行します:
    
    `./codexion number_of_coders time_to_burnout time_to_compile time_to_debug time_to_refactor number_of_compiles_required dongle_cooldown scheduler`
    ### 引数説明

   | 引数 | 説明 | 例 |
   | :--- | :--- | :--- |
   | `number_of_coders` | コーダーの数およびドングルの数 | `5` |
   | `time_to_burnout` | 最後のコンパイル開始時またはシミュレーション開始時から `time_to_burnout` ミリ秒以内にコンパイルを開始しなかった場合、コーダーはバーンアウトします | `1000` (ms) |
   | `time_to_compile` | コーダーがコンパイルに費やす時間。この間、コーダーは2つのドングルを保持する必要があります | `200` (ms) |
   | `time_to_debug` | コーダーがデバッグに費やす時間 | `200` (ms) |
   | `time_to_refactor` | コーダーがリファクタリングに費やす時間。リファクタリングフェーズ完了後、コーダーは即座にドングルを取得して再度コンパイルを試みます | `200` (ms) |
   | `number_of_compiles_required` | すべてのコーダーが少なくともこの回数コンパイルを実行した場合、シミュレーションは停止します。それ以外の場合、コーダーがバーンアウトした時点で停止します | `5` |
   | `dongle_cooldown` | 解放されたドングルは、クールダウン時間が経過するまで利用できません | `50` (ms) |
   | `scheduler` | 複数のコーダーがドングルを要求した際に、誰に割り当てるかを決定する調停ポリシー。値は `fifo` または `edf` のいずれかでなければなりません。`fifo` は First In, First Out（最初に要求が到着したコーダーに付与）、`edf` は Earliest Deadline First（デッドライン = `last_compile_start` + `time_to_burnout`）を意味します | `fifo` |
   ### 実行例
   ```
   ./codexion 5 1000 200 200 200 5 50 fifo
   ```

## 追加セクション

### 1. ブロッキング処理の考慮ケース
#### **デッドロック防止とコフマンの条件**
#### 📚 参考: コフマンの4つの必要条件
デッドロックは、以下の 4 つの条件が同時に成立した場合にのみ発生します。いずれか 1 つの条件を破ることで、デッドロックを完全に防ぐことができます:
1. **相互排他 (Mutual Exclusion)**: リソースを共有できません。同時に 1 つのスレッドのみがリソースを占有できます。
2. **保持と待機 (Hold and Wait)**: 少なくとも 1 つのリソースを保持しているスレッドが、他のスレッドによって保持されている追加のリソースの取得を待機します。
3. **非先取り (No Preemption)**: リソースを強制的に奪い取ることはできません。保持しているスレッドによって自発的に解放される必要があります。
4. **循環待機 (Circular Wait)**: スレッドの閉じた依存関係チェーン $\{P_1, P_2, \dots, P_n\}$ が存在し、$P_1$ が $P_2$ の保持するリソースを待ち、$P_2$ が $P_3$ を待ち、… $P_n$ が $P_1$ を待ちます。

#### 🛠️ 当実装での解決策: 循環待機の破壊
* **破った対象条件**: 循環待機 (Circular Wait)。
- **アドレス昇順によるロック取得**: 複数のドングルを取得する際、スレッドはメモリアドレスを比較し、厳密に昇順でロックを取得します。
- **構造的ループ防止**: グローバルなロック階層を強制することで、物理的に循環待機チェーンが形成されるのを防ぎます。

#### **スターベーション（餓死）の防止**
- **ヒープ型優先順位付け**: `dongle` 構造体に二分ヒープを埋め込み、最後のコンパイル時刻/デッドライン指標を優先度として、バーンアウトに最も近いコーダーをルート（先頭）に保持します。
- **v1.5 決定論的タイブレイカー**: 優先度/デッドラインが衝突した場合、先に挿入されたエントリ（FIFO挿入順）を優先することで、確定的に優先順位を解決します。

#### **ドングルのクールダウン処理**
- **有効期限の追跡**: `dongle` 構造体はクールダウン有効期限タイムスタンプを保持し、コーダーがコンパイルフェーズを終了した際に更新します。
- **タイムアウト付き待機**: ドングルを取得しようとする際、コーダーはこのタイムスタンプを検査します。クールダウンがまだ終了していない場合、コーダーは `pthread_cond_timedwait` を使用して期限までスリープします。

#### **高精度なバーンアウト検出**
- **非ビジーウェイト型の監視**: CPU の過剰消費を防ぐため、ビジーウェイト（ポーリング）の代わりに `pthread_cond_timedwait` を使用します。
- **バーンアウト判定基準**: 各コーダーの最終コンパイルタイムスタンプを追跡し、`current_time - last_compile_time >= time_to_burnout` に達した時点でバーンアウトを発動します。
- **ピンポイントな起床**: 監視スレッドは、バーンアウトに最も近いコーダーのデッドラインに合わせて動的に起床します。スケジューラオーバーヘッドのため、検知は通常 **2〜3 ms** 以内に発生します。
- **安全な終了処理**: 検知時、監視スレッドは即座に `stop_flag` を立てます。コーダーは各アクションの前に `stop_flag` をチェックし、無駄な処理を行わずにクリーンに終了します。
- **レースコンディション防止**: `stop_flag` へのアクセスおよびチェックは、専用の Mutex によってシリアライズ（排他制御）されています。

#### **ログのシリアライズ**
- 同時実行中のメッセージの割り込み（混ざり合い）を防ぐため、単一の `log_mutex` を使用してログ出力をシリアライズしています。


### 2. スレッド同期メカニズム

## スレッド同期メカニズム
共有状態やタイムスタンプは厳密な Mutex 保護（`pthread_mutex_t`）によってデータレースを防ぎ、条件変数を用いたタイムアウト付き待機（`pthread_cond_timedwait`）によって CPU 資源を無駄遣いするビジーウェイトを排除しています。

```c
typedef struct s_SharedContext
{
    pthread_mutex_t lock;      // stop_flag の読み書きを保護・シリアライズ
    pthread_mutex_t log_lock;  // 並行ログ出力をシリアライズ
}   t_SharedContext;

typedef struct s_Dongle
{
    pthread_cond_t  *cond;     // 優先度ヒープのルートにいるコーダーに通知する条件変数
    pthread_mutex_t lock;      // ドングルの取得状態を保護
}   t_Dongle;

typedef struct s_Coder
{
    pthread_cond_t  cond;      // ビジーウェイトを避けるため pthread_cond_timedwait で使用
    pthread_mutex_t lock;      // 最終コンパイルタイムスタンプへのアクセスを保護
}   t_Coder;

typedef struct s_Monitor
{
    pthread_cond_t  cond;      // ビジーウェイトを避けるため pthread_cond_timedwait で使用
    pthread_mutex_t lock;      // タイムアウト付き待機の調整のため cond とペアで使用する Mutex
}   t_Monitor;
```
